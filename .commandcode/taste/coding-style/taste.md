# User Taste — Coding Style & Architecture

- Zero tolerance for primitive domain contracts: no bare str, int, float, bool, dict, tuple, list, set, Mapping, Sequence, object, or Any as architectural contracts when values represent real domain concepts. Use explicit domain models instead. Confidence: 0.95
- Uses Enums aggressively for all genuinely closed finite domains (datasets, policies, strategies, statuses, failure reasons, aggregation methods, etc.). External CLI/YAML strings must be converted to Enums at the boundary. No magic strings for domain state. Confidence: 0.95
- `Any` is forbidden in production-domain architecture except when an unavoidable third-party interface requires a tightly isolated adapter. Prefer typed models, Protocols, generics, explicit unions, library type stubs, typed adapters. Confidence: 0.95
- Value objects over primitive obsession: create explicit value/domain types where values carry invariants or distinct meaning (client IDs, seeds, fractions, probabilities, thresholds, sample counts, artifact paths). Validate invariants at construction. Confidence: 0.9
- Typed configuration pipeline: file → parse → validate → typed configuration model → domain. No raw YAML/JSON dicts propagated through the application. Centralize scientific/configurable values. Confidence: 0.9
- `canonical` naming is forbidden in code identifiers (no canonical_name, canonical_id, canonical_path, canonicalize, etc.). Replace with real domain meaning. Confidence: 0.95
- Remove non-runtime research/manuscript infrastructure from production code: no claim registries, bibliography/citation management, manuscript prose generation, explanatory research modules. Legitimate provenance/metadata/audit artifacts are fine. Confidence: 0.9
- Clean code: small cohesive modules, strong typing, immutability where useful, deterministic execution, low coupling, minimal duplication, clear dependency direction, reproducibility. Remove dead code, unnecessary wrappers/factories, pass-through abstractions, excessive inheritance, mutable global state, magic values/strings, broad exception swallowing, giant functions, god classes, commented-out code, compatibility layers. Confidence: 0.9
- TODO zero-tolerance: no TODO, FIXME, HACK, XXX, NotImplementedError, placeholder, stub, or temporary in production code. Implement properly or remove after verifying nothing requires it. No fake-success returns or unfinished handlers. Confidence: 0.95
- Prefers Pydantic strict typed configuration models (frozen=True, extra="forbid") for configuration. Confidence: 0.8
- Prefers architecture enforcement via AST-aware tests for primitive leakage, Any usage, missing enums, stringly-typed domains, dependency-direction violations, and roadmap/file-tree drift. Confidence: 0.85
- Prefers import-linter contracts enforcing layered architecture (domain independent, config depends only on domain, lower layers never depend on orchestration). Confidence: 0.8
- Prefers strict pyright type checking. Uses typing.cast or typed adapters for third-party libraries lacking type stubs rather than introducing Any. Confidence: 0.85
- Prefers vectorized/dataframe/library operations over Python loops for large datasets where it improves performance without obscuring correctness. Confidence: 0.8
- Zero backwards compatibility in refactors: no deprecated aliases, fallback imports, re-export shims, compatibility classes/enums, legacy config keys, old paths, or migration wrappers. The final repository must look as if the new architecture had always been the architecture. Confidence: 0.95
- Governed scientific/experimental values must be centralized in configuration, never hardcoded in implementation code; a refactor that introduces hardcoded thresholds/counts/seeds violates the rules even when the numbers came from a new function. Confidence: 0.9
- Library choices are judged on correctness, maintainability, and numerical reliability: do not reimplement mature numerical/statistical/serialization functionality when a reliable library exists, but do not add dependencies merely to save a few lines of trivial code. Confidence: 0.85
